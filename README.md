# 音序 Muse · BGM 创作

写一句「雨天咖啡馆里的慵懒钢琴，60 秒」，得到一段可以直接用的纯器乐背景音乐，再试听、用对话继续改、调四条分轨、导出成 WAV。当前版本 **v0.3.0**：Windows 桌面版，以及一个只有本地作曲、可以离线运行的网页版。

**两种做音乐的方式**

- **本地作曲**：一个符号作曲器加一个纯程序合成器。离线、免费、不需要任何账号，同样的设置永远得到同样的音乐。22 种风格、14 种主奏乐器、24 个调，48 kHz 四分轨，响度对齐到 −16 LUFS。
- **云端 AI 音乐服务**（仅桌面版，用你自己的密钥）：腾讯云 TokenHub、火山引擎、阿里云百炼 Fun-Music、ElevenLabs。每次生成都是一次付费请求，发送前会先询问；得到的是一条混合音轨，没有分轨。

**制作人**把你的话变成制作方案。**离线规则**随时可用（网页版也有）；也可以在设置里接入自己的**大模型**——Claude、任何 OpenAI 兼容接口，或本机的 Ollama——来理解描述、安排编曲。大模型出错时自动改用离线规则并说明原因。

> **如实说明**：四家云端音乐服务和托管的大模型都只在本机模拟的服务上跑通过，**没有用真实付费账号验证过**；安装包没有实际运行过；只在 Chromium / Electron 里测试过；**没有人听过生成的音频**——响度、平衡这些结论全部来自测量，好不好听需要你自己判断。详见 [docs/QA.md](docs/QA.md)。

**智能体接手**：先读 [HANDOFF.md](HANDOFF.md) 的 S00、S01，再按任务定位章节。`AGENTS.md` / `CLAUDE.md` 是简短入口。

## 快速开始

**直接运行**：双击根目录的 `启动音序.cmd`。它启动 `release\Muse-BGM-Portable-0.3.0-x64.exe`（与 `package.json` 版本一致的便携版）；这个文件由 `npm run dist` 生成，`release/` 不进 Git。没有任何账号和密钥也能使用完整的本地作曲。

| 发行文件（`release/`） | 说明 |
| --- | --- |
| `Muse-BGM-Portable-0.3.0-x64.exe` | 便携版，单个文件，双击即用（每次启动先解压，比安装版慢几秒） |
| `Muse-BGM-Setup-0.3.0-x64.exe` | 安装版：只为当前用户安装，不需要管理员权限，创建桌面快捷方式「音序 Muse」，卸载时保留作品和设置。**这个安装包没有实际运行过** |

两个文件都没有代码签名，第一次运行时 Windows SmartScreen 会拦一下：点「更多信息」→「仍要运行」。校验值在 `release/SHA256SUMS.txt` 和 [docs/QA.md](docs/QA.md)。

> **不要再运行 0.1.0 / 0.2.0 的旧程序。** 旧版和 0.3 共用同一个数据目录（`%APPDATA%\Muse BGM`），但读不懂 0.3 的作品：它会把 0.3 的作品改写成旧引擎作品并丢掉对话记录，遇到新风格时它的整个作品列表都打不开。`release/` 里保留的旧 EXE 只作存档。用 0.2 做的作品在 0.3 里可以原样打开（标有「旧版引擎」），也可以导入 0.2 导出的工程 JSON。

**从源码运行**（需要 Node.js 22.12 或更新）：

```powershell
Set-Location D:\makeBGM
npm ci
npm run desktop      # 构建并打开桌面版
```

| 命令 | 用途 |
| --- | --- |
| `npm run dev` | 浏览器开发版（只有本地作曲） |
| `npm run build` / `npm run build:web` | 桌面版渲染层到 `dist/`；网页版到 `dist-web/` |
| `npm run typecheck`、`npm run format:check` | 类型检查（`src/`、`tests/`、`scripts/`）；排版检查 |
| `npm test` | 全部单元测试，约 1 分钟；`npm run test:fast` 只跑不合成音频的部分 |
| `npm run test:all` | 两个构建 + 单元测试 + 网页版和三个 Electron 端到端套件，约 3.5 分钟 |
| `npm run dist` → `npm run test:packaged` | 生成安装版和便携版；检查发行程序 |
| `npm run demos`、`npm run audit:audio` | 渲染 22 段风格示例；输出客观音频指标 |

全部脚本和各套件覆盖什么见 HANDOFF S09、S10。Electron 套件读取已有的 `dist/`，改过界面后先 `npm run build`；所有套件都使用系统临时目录下的一次性数据目录，不会碰 `%APPDATA%\Muse BGM`。

## 怎么用

1. 在「创作」里写下场景、情绪、乐器或用途，或者只点一个风格。可以固定时长（15 / 30 / 60 / 90 / 120 秒）和结构（循环片段 / 完整结尾），选择生成引擎和制作人。输入框下面会实时显示离线规则的理解。
2. 生成后在波形上播放、定位；段落和和弦显示在波形上方。空格播放，← / → 定位，`L` 循环试听，`Ctrl+E` 导出。
3. 继续对话：「慢一点」「换成古筝」「不要鼓」「加长 15 秒」「速度降到 90」。每次修改都是一个新版本，旧版本保留；制作人会如实说明旋律是保持不变、按新设置重新演绎，还是换了新的。
4. 「声音微调」里直接改风格、速度、调性、主奏乐器、情绪能量、旋律丰富度、空间混响、时长和结构，点「应用调整」生成新版本；「换一版旋律」保留设置、重写旋律。
5. 「混音」里旋律 / 和声 / 贝斯 / 鼓组四条推子即时生效并自动保存，可以静音或独奏试听（独奏不影响导出）。
6. 「导出」：完整混音 WAV（循环片段可以重复 2 或 4 遍）、单独一轨，或可重新导入的工程 JSON；云端作品还可以导出服务商返回的原始音频。

| 我的作品 | 改名、收藏、搜索、排序、8 秒内可撤销的删除、导入工程、读不了的记录可以导出原始数据 |
| 版本 | 每次生成都是新版本；同一首曲子的各个版本共享一条对话，可以回到任何一版 |

本地作曲是「乐理规则 + 确定性随机 + 程序合成」：好处是离线、可控、可重建、不计费；它不是在本机运行的生成式音乐大模型，没有人声，音色是合成的。

## 制作人大模型与云端服务（可选，仅桌面版）

在「设置 → 制作人大模型」里选择服务、填写密钥和模型名：内置 Claude、DeepSeek、通义千问、豆包、智谱、Kimi、腾讯混元、OpenAI、本机 Ollama 和自定义 OpenAI 兼容接口。在「设置 → AI 音乐服务」里保存音乐服务的凭据，再在「生成引擎」里选择它。**开通步骤、每一项填什么、费用和排错见 [API 配置指南](docs/API配置指南.md)。**

用云端服务前需要知道的：

- 每次都是**重新生成整首**，按服务商计费，不保留原旋律。发送、应用调整、换一版都会先弹出确认（可以勾选本次会话不再提示）。
- 应用从不自动重试一次生成。取消只是停止等待，已提交的请求仍可能完成并计费。
- 结果先保存、再解码。保存失败时作品留在当前窗口并提示先导出；音乐已生成但文件没下载下来时可以点「重新下载」，不会再次计费（只在本次运行内有效）。这些情况下关闭窗口会先询问。
- 大模型失败、而生成引擎又是付费的云端服务时，应用会停下来问你，不会拿离线规则的方案直接去花钱。

## 数据留在哪里，什么会发出去

- **本地作曲和离线规则**：不发任何网络请求。界面所在的页面被策略禁止联网（`connect-src 'none'`）；应用没有自动更新、没有统计上报。
- **作品**：存在本机的 IndexedDB（`muse-bgm` / `projects`）。本地作品只存设置、旋律种子和对话，打开时重新合成；云端作品存服务商返回的音频本身。桌面版数据目录是 `%APPDATA%\Muse BGM`；设置 `MUSE_PORTABLE_DATA=1` 时便携版改用 EXE 旁的 `Muse-Data`。
- **密钥**：只保存在本机的 `music-credentials.json` 里，由 Windows 系统保护加密，界面读不回来。
- **用云端音乐服务时**：一段由应用写成的音乐描述（风格、速度、调、乐器等，永远要求纯音乐）、目标时长和你的密钥，发给你选的那一家服务商，只从主进程发出。
- **用大模型时**：你的话、最近最多 12 轮对话、当前的音乐设置和一段固定的系统提示词，发给你配置的那个模型服务（本机 Ollama 则只发给这台电脑）。不发送音频、作品库和音乐服务的密钥。
- **备份**：工程 JSON 不含音频和密钥，只能备份本地作品；云端作品请导出音频。

## 网页版

`npm run build:web` 生成 `dist-web/`：纯静态、相对路径、完全离线，只有本地作曲，可以直接放进 iframe（计划嵌在 `https://starwright.xyz/play/yinxu/`；门户页面尚未上线）。界面按 320 px 起不出现横向滚动来设计，端到端套件核对的是 390 px 宽的触屏和 1000×760 的内嵌框架。作品保存在浏览器里，多个标签页之间会同步，与 Windows 版不共享。云端服务和大模型在网页版里显示为「桌面版可用」。

## 示例与试听

- `examples/`：[晴空漫步（30 秒）](examples/晴空漫步.wav) 和[它的工程文件](examples/晴空漫步.muse.json)；[一个 0.2 时代的工程](examples/legacy-v0.2-夏日小事.muse.json)（可以导入，会在旧版引擎上打开）。
- `demos/`：22 种风格各一段约 40 秒、有结尾的小曲和一份 `index.md`（速度、调、配器、编曲思路）。这个文件夹不进 Git，用 `npm run demos` 生成（约半分钟，每次得到逐字节相同的文件）；`npm run demos -- --styles jazz,rock --seconds 60` 可以只出几种、换长度。
- 改了作曲器或合成器之后，用 `npx tsx scripts/render-demos.ts --example` 重写 `examples/` 里的示例（测试会核对它与当前引擎一致）。

## 限制与现状

- 真实付费账号（四家音乐服务、Claude 和其他托管大模型）都没有测试过；真实调用过的只有本机 Ollama。第一次用真实密钥时请从最短的时长开始，并到服务商控制台核对记录。
- 安装包没有运行过；两个 EXE 没有签名；只有 Windows x64；只在一台 Windows 11 电脑上测试过。
- 网页版只在 Chromium 里测试过。
- 没有人审听过音频；音频质量由客观指标把关（22 种风格的响度、峰值、频谱、立体声、循环接缝等）。
- 云端作品没有分轨，时长和循环只是给服务的目标。
- 完整的验证记录见 [docs/QA.md](docs/QA.md)，已知限制和下一步见 HANDOFF S11。
