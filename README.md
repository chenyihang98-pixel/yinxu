# 音序 Muse · BGM 创作

点一个场景（「咖啡馆」「旅行风景」「游戏关卡」……），几秒钟就得到一段可以直接用的纯器乐背景音乐：听一听，点「下载音乐」拿到文件。不需要懂任何音乐知识，也不用读说明——这是默认的**简单模式**。想自己掌控的人可以切到**专业模式**：写一句「雨天咖啡馆里的慵懒钢琴，60 秒」，用对话继续改、调四条分轨、按需导出。当前版本 **v0.4.0**（2026-11-02；简单模式是这一版新加的，专业模式就是 0.3 的界面）：Windows 桌面版，以及一个只有本地作曲、可以离线运行的网页版。

**两种做音乐的方式**

- **本地作曲**：一个符号作曲器加一个纯程序合成器。离线、免费、不需要任何账号，同样的设置永远得到同样的音乐。22 种风格、14 种主奏乐器、24 个调，48 kHz 四分轨，响度对齐到 −16 LUFS。
- **云端 AI 音乐服务**（仅桌面版，用你自己的密钥）：腾讯云 TokenHub、火山引擎、阿里云百炼 Fun-Music、ElevenLabs。每次生成都是一次付费请求，发送前会先询问；得到的是一条混合音轨，没有分轨。

**制作人**把你的话变成制作方案。**离线规则**随时可用（网页版也有）；也可以在设置里接入自己的**大模型**——Claude、任何 OpenAI 兼容接口，或本机的 Ollama——来理解描述、安排编曲。大模型出错时自动改用离线规则并说明原因。不管用哪一种，回复里「改了什么」都由应用按实际发生的改动写出；大模型自己的话只作为「模型说明」附在下面，说得与实际改动不符的不显示。

> **如实说明**：四家云端音乐服务和托管的大模型都只在本机模拟的服务上跑通过，**没有用真实付费账号验证过**；安装包没有实际运行过；只在 Chromium / Electron 里测试过；**没有真人用户试过简单模式**；**没有人听过生成的音频**——响度、平衡这些结论全部来自测量，好不好听需要你自己判断。详见 [docs/QA.md](docs/QA.md)。

**智能体接手**：先读 [HANDOFF.md](HANDOFF.md) 的 S00、S01，再按任务定位章节。`AGENTS.md` / `CLAUDE.md` 是简短入口。

## 快速开始

**直接运行**：双击根目录的 `启动音序.cmd`。它启动 `release\Muse-BGM-Portable-0.4.0-x64.exe`（与 `package.json` 版本一致的便携版）；这个文件由 `npm run dist` 生成，`release/` 不进 Git。没有任何账号和密钥也能使用完整的本地作曲。

| 发行文件（`release/`） | 说明 |
| --- | --- |
| `Muse-BGM-Portable-0.4.0-x64.exe` | 便携版，单个文件，双击即用（每次启动先解压，比安装版慢几秒） |
| `Muse-BGM-Setup-0.4.0-x64.exe` | 安装版：只为当前用户安装，不需要管理员权限，创建桌面快捷方式「音序 Muse」，卸载时保留作品和设置。**这个安装包没有实际运行过** |

两个文件都没有代码签名，第一次运行时 Windows SmartScreen 会拦一下：点「更多信息」→「仍要运行」。校验值在 `release/SHA256SUMS.txt` 和 [docs/QA.md](docs/QA.md)，更新说明在 `release/RELEASE-NOTES-0.4.0.md`。从 0.3 升级直接用 0.4 打开即可：数据格式没有变，作品原样都在；第一次打开是简单模式，点角落的「专业模式」就回到熟悉的界面。`release/` 里的 0.3.0 只作存档。

> **不要再运行 0.1.0 / 0.2.0 的旧程序。** 旧版和 0.3 / 0.4 共用同一个数据目录（`%APPDATA%\Muse BGM`），但读不懂新的作品：它会把它们改写成旧引擎作品并丢掉对话记录，遇到新风格时它的整个作品列表都打不开。`release/` 里保留的旧 EXE 只作存档。用 0.2 做的作品在 0.3 / 0.4 里可以原样打开（标有「旧版引擎」），也可以导入 0.2 导出的工程 JSON。

**从源码运行**（需要 Node.js 22.12 或更新）：

```powershell
Set-Location D:\makeBGM
npm ci
npm run desktop      # 构建并打开桌面版
```

| 命令 | 用途 |
| --- | --- |
| `npm run dev` | 浏览器开发版（只有本地作曲） |
| `npm run build` / `npm run build:web` | 桌面版渲染层到 `dist/`；网页版到 `dist-web/` |
| `npm run typecheck`、`npm run format:check` | 类型检查（`src/`、`tests/`、`scripts/`）；排版检查 |
| `npm test` | 全部单元测试，约 1 分钟；`npm run test:fast` 只跑不合成音频的部分 |
| `npm run test:all` | 两个构建 + 单元测试 + 网页版和三个 Electron 端到端套件，约 5.5 分钟 |
| `npm run dist` → `npm run test:packaged` | 生成安装版和便携版；检查发行程序 |
| `npm run demos`、`npm run audit:audio` | 渲染 22 段风格示例；输出客观音频指标 |

全部脚本和各套件覆盖什么见 HANDOFF S09、S10。Electron 套件读取已有的 `dist/`，改过界面后先 `npm run build`；所有套件都使用系统临时目录下的一次性数据目录，不会碰 `%APPDATA%\Muse BGM`。

## 怎么用

### 简单模式（默认）

打开 → 点一下 → 听到音乐 → 点一下 → 拿到文件。

1. 「做音乐」里点一个场景卡片（日常 Vlog、咖啡馆、旅行风景、可爱萌宠、学习专注、睡前放松、运动健身、游戏关卡、史诗大片、国风古韵、浪漫温馨、科技产品），或者「更多风格」里的一个，立刻开始做，不需要再点「生成」。也可以用一句话说说想要什么，再点「做一首」。长度默认「自动」，也可以选 30 秒、1 分钟、2 分钟。
2. 做好会自动播放。上面是一行人话说明（例如「慵懒放松 · 约 1 分钟 · 可以循环播放」：循环的曲子按整小节对齐，差一点时说「约」），点标题可以改名（同一首的每一版一起改）。
3. 「下载音乐」直接保存整首（桌面版弹出系统保存框，网页版直接下载；文件名就是标题；按钮本身会显示「已保存」）。「换一首」保留设置换一段新旋律；「重新挑」回到场景页。
4. 觉得哪里不对，点一下就改：更欢快、更安静、快一点、慢一点、长一点、短一点、换个乐器、去掉鼓（或加点鼓）、做成循环（或加个结尾），也可以在框里直接说「鼓声小一点」。改完会说清楚改了什么（例如「改好了：节奏快了一点，旋律没变。」），点「撤销」回到上一版；「上一版 / 下一版」可以来回听，回到哪一版，「我的音乐」里这首就是哪一版。改不了的时候（例如已经是最长的 2 分钟）会直接说为什么，不会白做一版。
5. 「我的音乐」里每首曲子一张卡片（改过几次会写「共 3 版」），可以搜索，播放和下载都在这一页进行，删除整首（8 秒内可以撤销）。
6. 页面角落的「专业模式」或「设置 → 常规」切换界面；两种模式用的是同一批作品，切换不会丢掉任何东西，选择会记在这台设备上。

桌面版在「设置 → AI 音乐服务」配置好云端服务后，场景页会多一个「用 AI 服务生成（服务名，按次付费）」开关，默认关；打开后每次生成和每次修改都会先问你（与专业模式相同的付费确认和保护；改不了的修改不会走到付费这一步）。保存了制作人大模型时，简单模式用它理解你**自己写的话**（框下会注明）；场景卡片和一键微调是固定的说法，始终用内置方式，不联网也不用等；大模型没有回应时改用内置方式，并在改动说明后面说一句。

### 专业模式

1. 在「创作」里写下场景、情绪、乐器或用途，或者只点一个风格。可以固定时长（15 / 30 / 60 / 90 / 120 秒）和结构（循环片段 / 完整结尾），选择生成引擎和制作人。输入框下面会实时显示离线规则的理解。
2. 生成后在波形上播放、定位；段落显示在波形上方，和弦显示在波形下方。空格播放，← / → 定位，`L` 循环试听，`Ctrl+E` 导出。
3. 继续对话：「慢一点」「换成古筝」「不要鼓」「加长 15 秒」「速度降到 90」。每次修改都是一个新版本，旧版本保留；回复逐项列出实际改了什么，并如实说明旋律是保持不变、按新设置重新演绎、只保留节奏型，还是换了新的。
4. 「声音微调」里直接改风格、速度、调性、主奏乐器、情绪能量、旋律丰富度、空间混响、时长和结构，点「应用调整」生成新版本；「换一版旋律」保留风格、速度、调性和乐器，重写旋律（和弦走向通常也跟着重写，回复里会说明）。没应用的修改会跟着作品记住，重启后还在。
5. 「混音」里旋律 / 和声 / 贝斯 / 鼓组四条推子即时生效并自动保存，可以静音或独奏试听（独奏不影响导出）。
6. 「导出」：完整混音 WAV（循环片段可以重复 2 或 4 遍）、单独一轨，或可重新导入的工程 JSON；云端作品还可以导出服务商返回的原始音频。

本地作曲是「乐理规则 + 确定性随机 + 程序合成」：好处是离线、可控、可重建、不计费；它不是在本机运行的生成式音乐大模型，没有人声，音色是合成的。

## 制作人大模型与云端服务（可选，仅桌面版）

在「设置 → 制作人大模型」里选择服务、填写密钥和模型名：内置 Claude、DeepSeek、通义千问、豆包、智谱、Kimi、腾讯混元、OpenAI、本机 Ollama 和自定义 OpenAI 兼容接口。在「设置 → AI 音乐服务」里保存音乐服务的凭据，再在「生成引擎」里选择它。**开通步骤、每一项填什么、费用和排错见 [API 配置指南](docs/API配置指南.md)。**

用云端服务前需要知道的：

- 每次都是**重新生成整首**，按服务商计费，不保留原旋律。发送、应用调整、重新生成一版都会先弹出确认（可以勾选本次会话不再提示）；确认框出现后的半秒内不接受点击和回车，连点或按住回车不会误发。服务不接受的时长（例如火山引擎的 15 秒）在付费确认之前就会先问你改成多少。
- 应用从不自动重试一次生成。取消只是停止等待，已提交的请求仍可能完成并计费。
- 结果先保存、再解码。保存失败时作品留在当前窗口并提示先导出。
- **已经付费但还没取回的结果不会被悄悄丢掉**：音乐已生成但文件没下载下来，或任务已提交但没等到结果时，每个页面顶部都会出现一条关不掉的横幅——「重新下载」再取一次（火山引擎的任务会继续查询），不会再次提交、不会再次计费；「放弃这次结果」要再确认一次。在取回或放弃之前，新的付费生成、打开别的作品、新建创作和关闭窗口都会先问你。这份结果只留在本次运行里：重新加载界面后横幅会回来，退出应用后就取不回了。
- 大模型失败、而生成引擎又是付费的云端服务时，应用会停下来问你，不会拿离线规则的方案直接去花钱。

## 数据留在哪里，什么会发出去

- **本地作曲和离线规则**：不发任何网络请求。界面所在的页面被策略禁止联网（`connect-src 'none'`）；应用没有自动更新、没有统计上报。
- **作品**：存在本机的 IndexedDB（`muse-bgm` / `projects`）。本地作品只存设置、旋律种子和对话，打开时重新合成；云端作品存服务商返回的音频本身。桌面版数据目录是 `%APPDATA%\Muse BGM`；设置 `MUSE_PORTABLE_DATA=1` 时便携版改用 EXE 旁的 `Muse-Data`。
- **密钥**：只保存在本机的 `music-credentials.json` 里，由 Windows 系统保护加密，界面读不回来。
- **用云端音乐服务时**：一段由应用写成的音乐描述（风格、速度、调、乐器等，永远要求纯音乐）、目标时长和你的密钥，发给你选的那一家服务商，只从主进程发出。
- **用大模型时**：你的话、最近最多 12 轮对话、当前的音乐设置和一段固定的系统提示词，发给你配置的那个模型服务（本机 Ollama 则只发给这台电脑）。不发送音频、作品库和音乐服务的密钥。
- **备份**：工程 JSON 不含音频和密钥，只能备份本地作品；云端作品请导出音频。

## 网页版

`npm run build:web` 生成 `dist-web/`：纯静态、相对路径、完全离线，只有本地作曲，可以直接放进 iframe（计划嵌在 `https://starwright.xyz/play/yinxu/`；门户页面尚未上线，所以网页版里「下载 Windows 版」的链接目前打不开）。界面按 320 px 起不出现横向滚动来设计，端到端套件核对的是 390 px 宽的触屏和 1000×760 的内嵌框架。作品保存在浏览器里，多个标签页之间会同步，与 Windows 版不共享。云端服务和大模型在网页版里显示为「桌面版可用」。

- `examples/`：[晴空漫步（30 秒）](examples/晴空漫步.wav) 和[它的工程文件](examples/晴空漫步.muse.json)；[一个 0.2 时代的工程](examples/legacy-v0.2-夏日小事.muse.json)（可以导入，会在旧版引擎上打开）。

- 改了作曲器或合成器之后，用 `npx tsx scripts/render-demos.ts --example` 重写 `examples/` 里的示例（测试会核对它与当前引擎一致）。

## 限制与现状

- 真实付费账号（四家音乐服务、Claude 和其他托管大模型）都没有测试过；真实调用过的只有本机 Ollama。第一次用真实密钥时请从最短的时长开始，并到服务商控制台核对记录。
- 没有真人用户试过简单模式（它按不懂音乐的人设计并走查过，但没有真正的用户用过）。设置里的两个凭据页仍是技术性的；配置了几家云端服务时，简单模式的开关只提供第一家。
- 安装包没有运行过；两个 EXE 没有签名；只有 Windows x64；只在一台 Windows 11 电脑上测试过（Windows 10 没有验证）。
- 四家云端服务里，经界面完整跑过一遍（对着模拟服务）的是腾讯云、火山引擎和阿里云；ElevenLabs 只有协议层的测试。
- 网页版只在 Chromium 里测试过。
- 没有人审听过音频；音频质量由客观指标把关（22 种风格的响度、峰值、频谱、立体声、循环接缝等）。
- 云端作品没有分轨，时长和循环只是给服务的目标。
- 一次 120 秒的本地渲染需要 300–400 MB 的工作内存；网页版在手机上建议用 15–60 秒的时长（没有在真实手机上测过）。
- 完整的验证记录见 [docs/QA.md](docs/QA.md)，已知限制和下一步见 HANDOFF S11。
