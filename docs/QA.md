## 自动化覆盖

单元测试覆盖规则解析、确定性作曲、循环接缝、四分轨 PCM、WAV 编码、工程导入校验与存储错误；另覆盖三家服务请求契约、火山 V4 签名、任务轮询、取消、响应大小、音频格式和下载域名检查。凭证测试覆盖多服务独立保存/删除、旧配置迁移与加密异常。模拟输入不含真实 API 密钥。

基础 UI 在真实 Electron 中生成并保存 15 秒本地音乐，验证播放/暂停/跳转、94 BPM 吉他调整、保留种子的 82 BPM 文字微调、静音与独奏、WAV/JSON 导出导入、搜索收藏和页面重载。导出 WAV 的采样与头信息经过校验，独奏和完整混音内容不同。

扩展回归覆盖：

- 六种情绪、15/30/60/120 秒及自定义时长。
- 中文静音/恢复、英文 unmute、不识别的微调提示。
- 取消不留半成品、双击只生成一次、空描述/空标题校验。
- 损坏/过大/不兼容工程拒绝后恢复，存储配额错误保留可听结果。
- 草稿参数不改变已生成声音的导出、延迟删除不清空另一首作品。
- 延迟 AudioContext 恢复不会在新建后意外播放，循环关闭后播放位置保持。
- 四家服务配置的缺密钥防护、无效参数、真实系统加密保存与单独移除。

原始报告保留完整逐项断言；测试使用隔离目录和虚拟凭证，不接触用户正式作品库。额外定向回归确认旧作品的时长元数据写回失败时，音乐仍可打开和播放，界面明确表示保存未完成。

## 三家云端模拟完整流程

`scripts/cloud-workflow.cjs` 先在临时 Electron 启动脚本里替换所有主进程 `fetch`，再载入真实应用；未知请求直接失败，并额外阻断 Chromium 的 HTTP/HTTPS 出站。模拟只替换服务端响应，UI、preload、IPC、服务适配器、解码、持久化与导出都使用真实实现。

| 服务路径 | 本地返回素材 | 结果 |
| --- | --- | --- |
| 腾讯 TokenHub 同步 hex | 3 秒 MP3 | UI 配置、纯音乐请求、解码播放和原始 MP3 导出通过 |
| 火山签名提交 → 两次查询 → CDN | 3 秒 M4A | 后付费 Action、v5.0 参数、轮询、解码与 M4A 原样导出通过 |
| 阿里业务空间接口 → 音频 URL | 3 秒 WAV | 模型/空间请求、纯音乐参数、下载、解码与 WAV 原样导出通过 |

三首作品分别请求 15/30/15 秒，而素材实际为 3 秒；已断言保存的实际时长和作品库显示为 3 秒。这样验证了 App 不把期望时长冒充实际时长，不代表真实模型只会返回 3 秒。

还检查了：三家配置重载后保留、删除腾讯凭证不影响另外两家、未配置时不提交、401 可恢复且不自动重试、双击只产生一条提交、CDN 不携带密钥或签名、已保存云端音频离线重新打开。原始导出与素材逐字节相同。素材位于 `tests/fixtures/`，由本地示例 WAV 转换而来。
